# tayori MVP 手動動作確認手順書

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-07-24 |
| 対象 | MVP機能6項目・5画面構成（+補助2画面）の一連の動作確認 |
| 前提 | `firestore.rules`・`storage.rules`がFirebase Consoleにデプロイ済みであること（`docs/セットアップ手順書.md`章4参照） |
| 準備するもの | Googleアカウント2つ（招待受諾の確認に2アカウント目が必要） |

---

## 0. 事前準備

- [ ] `npm run dev`でローカルサーバーを起動し、`http://localhost:3000`にアクセスできる
- [ ] Firebase Console → Firestore Database → ルール で、現在公開されているルールが`firestore.rules`の内容と一致している
- [ ] Firebase Console → Storage → Rules で、現在公開されているルールが`storage.rules`の内容と一致している
- [ ] メインアカウント（A）とサブアカウント（B、招待受諾確認用）の2つのGoogleアカウントを用意する

---

## 1. ログイン（画面1）

1. `http://localhost:3000`にアクセスする
2. 未ログイン状態のため`/login`へリダイレクトされることを確認する
3. 「Googleでログイン」ボタンをクリックし、アカウントAでログインする
4. ログイン成功後、ホーム画面（`/`）へ遷移することを確認する

**期待結果**: ログイン後にホーム画面が表示される

---

## 2. ホーム（アルバム一覧、画面2）

1. アルバムが0件の場合、「まだアルバムがありません」等の空状態表示とアルバム作成導線が表示されることを確認する
2. 「＋新しいアルバム」ボタンをクリックし、`/albums/new`へ遷移することを確認する

**期待結果**: 空状態でもエラーにならず、作成導線が機能する

---

## 3. アルバム作成（画面3）

1. アルバム名を入力せずに保存を試み、「アルバム名を入力してください」というバリデーションエラーが表示されることを確認する（境界値: 51文字以上でも同様にエラーが出ることを確認する）
2. アルバム名（例: 「テストアルバム」）を入力し、保存する
3. 作成成功後、アルバム詳細画面（`/albums/{albumId}`）へ遷移することを確認する
4. ホーム画面に戻り、作成したアルバムが一覧に表示されることを確認する

**期待結果**: バリデーションが機能し、正常系では作成後にアルバム詳細へ遷移する

---

## 4. アップロード（画面5）

1. アルバム詳細画面で「アップロード」ボタンをクリックし、`/albums/{albumId}/upload`へ遷移する
2. 画像ファイル（JPG/PNG等）と動画ファイル（MP4等）を選択する
3. **選択直後は即アップロードされず、確定前プレビュー一覧（サムネイル付き）が表示される**ことを確認する
4. プレビュー一覧で1件をチェックボックスで選択し、「選択項目を削除」でアップロード対象から外せることを確認する
5. 「保存」ボタンを押し、一括アップロードが開始されることを確認する（進捗表示、完了後に成功表示）
6. 対応していないファイル形式・サイズ超過ファイルを選択し、エラーメッセージが表示されることを確認する（画像50MB超・動画500MB超は用意が難しければ省略可）
7. アップロード完了後、アルバム詳細画面に戻り、グリッドにメディアが表示されることを確認する

**期待結果**: 確定前プレビュー→保存→アップロードのフローが機能し、グリッドに反映される

---

## 5. メディアプレビュー単体画面（補助画面）

1. アルバム詳細画面のグリッドから、アップロードした画像をクリックする
2. `/albums/{albumId}/media/{mediaId}`へ遷移し、画像が`object-contain`で表示されることを確認する
3. 投稿者情報・ファイル名・投稿日時が右サイドパネルに表示されることを確認する
4. ダウンロードリンクをクリックし、ファイルがダウンロードされることを確認する
5. アップロードした動画をクリックし、`<video controls>`で再生できることを確認する（再生・一時停止・音量操作がブラウザネイティブUIで可能）
6. ブラウザの戻る操作でアルバム詳細画面に戻れることを確認する

**期待結果**: 404にならず、画像/動画とも正しくプレビューできる

---

## 6. 権限管理（共有設定、画面7）

### 6-1. 導線確認
1. アルバム作成者（owner）としてアルバム詳細画面を開き、ヘッダーに「権限管理」リンクが表示されることを確認する
2. リンクをクリックし、`/albums/{albumId}/permissions`へ遷移することを確認する

### 6-2. メンバー招待（メールアドレス事前登録）
1. 「家族を招待」ボタンからモーダルを開く
2. アカウントBのメールアドレスを入力し、ロール（editorまたはviewer）を選んで招待する
3. メンバー一覧に「招待中」バッジ付きでアカウントBの行が表示されることを確認する
4. メールアドレス未入力・不正な形式でエラーが表示されることを確認する

### 6-3. 招待の受諾（アカウントB側での確認）
1. 別ブラウザ（またはシークレットウィンドウ）でアカウントBにログインする
2. アルバム詳細画面のURL（`/albums/{albumId}`）に直接アクセスする、またはアルバム作成者からURLを共有してもらいアクセスする
3. 自動的に招待が受諾され、アルバム詳細画面が表示される（403にならない）ことを確認する
4. 権限管理画面で、アカウントBが「招待中」から確定メンバーへ変わっていることを確認する（アカウントA側で確認）

### 6-4. 権限編集
1. アカウントA（owner）で、アカウントBの`canPost`等のチェックボックスを変更し、「変更を保存」する
2. 保存成功後、成功メッセージが表示されることを確認する
3. アカウントBでログインし直し、変更した権限（例: 投稿不可なら投稿権限がありませんと表示される）が反映されていることを確認する

### 6-5. 招待取り消し
1. 別のメールアドレスで新規招待を作成する
2. 招待中の行から「取り消し」を実行し、一覧から消えることを確認する

### 6-6. 権限が無いユーザーのアクセス制限
1. アカウントBを`canManage=false`のまま、`/albums/{albumId}/permissions`へ直接URLアクセスする
2. 「管理権限がありません」等のメッセージが表示され、編集画面が表示されないことを確認する

**期待結果**: 招待→受諾→権限編集→取り消しの一連の流れが機能し、権限の無いユーザーは弾かれる

---

## 7. 共有リンク（MVP機能5）

1. 権限管理画面の「家族を招待」モーダルで「URLをコピー」を実行する
2. クリップボードにアルバムURLがコピーされていることを確認する（別タブに貼り付けて確認）

---

## 8. 全体を通した確認事項

- [ ] 各画面でブラウザのF12コンソールにエラー（赤字）が出ていないか確認する
- [ ] `Missing or insufficient permissions`のようなFirestore/Storage権限エラーが出ていないか確認する（出た場合はRulesデプロイ内容を再確認する）
- [ ] モバイル幅（Chrome DevToolsのデバイスモード）でも主要画面のレイアウトが崩れていないか確認する
