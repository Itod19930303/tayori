## 無料枠に関する注意（着手前に必ず確認）

基本設計書の動画アップロード上限は **500MB/ファイル** だが、Firebase Storage（Sparkプラン）の無料枠は目安で以下の通り。

| リソース          | Spark無料枠の目安 |
| ----------------- | ----------------- |
| Storage容量       | 5GB               |
| Storage下り転送量 | 1GB/日            |
| Firestore読み取り | 50,000回/日       |
| Firestore書き込み | 20,000回/日       |

500MBの動画を数本アップロードするだけで容量・転送量の上限に近づく可能性がある。**運用中に上限へ到達した場合はアップロードが失敗する**ため、以下のいずれかの対応を推奨する。

- MVP運用では動画アップロード数・頻度を抑えて様子を見る
- 上限到達が近づいた場合はBlazeプラン（従量課金、無料枠を超えた分のみ課金）への切り替えを検討する

この手順書ではSparkプランでの開始のみを扱う。プラン変更は本書の対象外とする。

> **補足（2026-07-09追記）：** 2024年後半以降のFirebase仕様変更により、**Storageを新規作成する時点でBlazeプラン（従量課金）への切り替えが必須**になった。Sparkプランのままでは「Storageの作成」画面に「開始する」ボタンが表示されず、「プロジェクトをアップグレード」ボタンのみが表示される。Blazeプランに切り替えても上表の無料枠自体は維持されるが、見落としによる想定外課金のリスクに備えるため、章1.3.5「Blazeプランへの切り替えと自動課金停止の設定」を必ず実施すること。

## 1. Firebaseプロジェクトのセットアップ

**この章はブラウザでの手動操作が必須。Claude Codeは代行できないため、ユーザー自身が実施すること。**

### 1.1 プロジェクト作成

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログインする
2. 「プロジェクトを追加」をクリック
3. プロジェクト名を入力（例: `tayori` または `tayori-app`。既に使用されている場合は末尾に数字が付与される）
4. Google Analyticsの設定を聞かれた場合は「無効にする」を選択してよい（MVPでは不要）
5. プロジェクトが作成されるまで待つ
6. 作成後、料金プランが **Sparkプラン（無料）** になっていることを「使用量と請求額」画面で確認する

### 1.2 Webアプリの登録

1. プロジェクト概要画面で「</>」（Webアプリを追加）アイコンをクリック
2. アプリのニックネームを入力（例: `tayori-web`）
3. 「Firebase Hosting も設定する」はチェックしない（Vercelを使うため不要）
4. 「アプリを登録」をクリックすると、以下のような `firebaseConfig` が表示される

   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "tayori-xxxx.firebaseapp.com",
     projectId: "tayori-xxxx",
     storageBucket: "tayori-xxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:xxxxxxxx"
   }
   ```

5. **この画面を閉じずに、6つの値を控えておく**（後述の `.env.local` 作成で使用する）。この手順書自体はGit管理下に置くため、控えた値はこの手順書には書き込まず、`.env.local`（`.gitignore` 対象）にのみ記載すること

### 1.3 Authentication（Googleログイン）の有効化

1. 左メニュー「構築」→「Authentication」を開く
2. 「始める」をクリック
3. 「Sign-in method」タブで「Google」を選択し、有効にする
4. プロジェクトのサポートメール（自分のGoogleアカウントのメールアドレス）を選択して保存する

### 1.3.5 Blazeプランへの切り替えと自動課金停止の設定

**この節はブラウザ（Firebase Console / Google Cloud Console）での手動操作が必須。Claude Codeは代行できない。** 課金アカウントに関わる権限操作のため、必ずユーザー自身が実施すること（Cloud Functionsのコード自体は下書き済みのものを使ってよい）。

#### 1.3.5.1 前提

- Cloud Storage for Firebase を新規作成するには、Sparkプラン（無料）ではなく **Blazeプラン（従量課金）** への切り替えが必須（2024年後半以降のFirebase仕様変更）
- Blazeプランに切り替えても、章「無料枠に関する注意」に記載した無料枠（Storage容量5GB・下り転送量1GB/日など）は変わらず適用される。**無料枠を超えた分のみ課金される**
- 「見落としによる想定外課金」のリスクを避けるため、予算アラートに加えて自動課金停止の仕組みを設定する

#### 1.3.5.2 Blazeプランへのアップグレード

1. Firebase Console左下（または「Storage」画面の「プロジェクトをアップグレード」ボタン）からアップグレード画面を開く
2. 「Blazeプラン（従量課金制）」を選択する
3. 支払い情報（クレジットカード等）を登録する
4. アップグレード完了後、Storageの作成画面に戻ると「開始する」ボタンが表示されるようになる（章1.5「Storageの作成」に進む）

#### 1.3.5.3 予算アラートの設定

1. https://console.cloud.google.com/billing にアクセスし、対象の請求先アカウントを開く
2. 左メニュー「予算とアラート」→「予算を作成」をクリック
3. 対象プロジェクト（`tayori-xxxx`）を選択する
4. 予算額を設定する（例: 月額500円〜1,000円程度。無料枠を大きく超えない想定額でよい）
5. アラートのしきい値を複数設定する（例: 50%・90%・100%）。デフォルトで請求先アカウントの管理者にメール通知が届く
6. 「完了」をクリックして保存する

#### 1.3.5.4 自動課金停止（Cloud Functions）の設定

見落とし対策として、予算のしきい値到達を検知し、Cloud Functionsで課金アカウントを自動的にプロジェクトから切り離す仕組みを設定する。

1. **新しい予算を別途作る必要はない。** 1.3.5.3で作成した予算と同じもの（同一ウィザードの最終ステップ、または作成後に予算を開いて編集）で「Pub/Sub トピックをこの予算に接続する」を有効にし、通知用のPub/Subトピック（例: `budget-alert-topic`）を作成する
   - 1.3.5.3の手順を「完了」まで進めて予算を作成済みの場合は、「予算とアラート」一覧から該当の予算名をクリックして開き、編集画面でPub/Sub連携を追加すればよい
   - トピックの選択欄で「新しいトピックを作成」を選び、トピック名（例: `budget-alert-topic`）を入力・作成する
2. **APIの有効化**
   1. https://console.cloud.google.com/apis/library にアクセス（対象プロジェクトが選択されていることを確認）
   2. 「Cloud Functions API」を検索し「有効にする」
   3. 「Cloud Billing API」を検索し「有効にする」
   4. 併せて以下も有効化する（Cloud Functions第2世代のデプロイに必要）：Cloud Build API、Artifact Registry API、Eventarc API、Cloud Pub/Sub API（Pub/Sub連携時に自動有効化済みのことが多い）

3. **Cloud Functionの実行アカウントに課金権限を付与**

   コードが `billing.projects.updateBillingInfo` を呼ぶには、関数を実行するサービスアカウントに課金管理者権限が必要。

   1. https://console.cloud.google.com/billing にアクセスし、対象の請求先アカウントを開く
   2. 左メニュー「アカウントの管理」（または「権限」）を開く
   3. 「アクセス権を追加」→ プリンシパルに `<プロジェクト番号>-compute@developer.gserviceaccount.com`（Cloud Functionsのデフォルト実行サービスアカウント。プロジェクト番号は「プロジェクトの設定」画面で確認できる）を入力
   4. ロールに「Billing Account Administrator」（`roles/billing.admin`）を選択して保存

4. **Cloud Functionのデプロイ（コンソールから）**

   1. https://console.cloud.google.com/functions にアクセスし「ファンクションを作成」をクリック
   2. 環境: 「第2世代」を選択
   3. 関数名: `stopBillingOnBudgetAlert`
   4. リージョン: `asia-northeast1`
   5. トリガー: 「Cloud Pub/Sub」を選択する
      - 「直通（Direct）」と「Eventarc」の選択を求められた場合は **「直通」を選ぶ**（Pub/Subメッセージを直接受け取るシンプルな方式で、今回のようなPub/Sub単独トリガーに適している。Eventarcは他のイベントソースと連携する高度な用途向けのため今回は不要）
      - 手順1で作成したトピック（`budget-alert-topic`）を選ぶ
      - **補足：** GoogleのUI統合により、この操作は `console.cloud.google.com/run/create` （Cloud Run経由）の画面に遷移する場合がある。機能的には第2世代Cloud Functionsのデプロイと同じなので、そのまま進めてよい
      - 「直通」を選ぶと「直接的な Pub/Sub サブスクリプション」というサイドパネルが開く。トピックが正しく選択されていることを確認し、警告ボックスに表示される追加のIAMロール付与（`roles/run.invoker` ・ `roles/iam.serviceAccountTokenCreator`。手順3のBilling Admin権限とは別に必要）は「**すべて付与**」ボタンで一括付与し、「保存」をクリックする
      - **トラブルシューティング：** 「すべて付与」実行時に `The policy contains a non-existent service account.` というエラーが出ることがある。これはPub/Sub用のGoogle管理サービスアカウント（`service-<プロジェクト番号>@gcp-sa-pubsub.iam.gserviceaccount.com`）がまだ作成されていないために起きる一時的な不具合（Pub/Sub API有効化直後によく発生する）。以下の順に対処する
        1. 数分待ってから「すべて付与」を再実行する
        2. それでも失敗する場合、Cloud Shell（Console右上の `>_` アイコン）で以下を実行してサービスアカウントを明示的に作成する
           ```bash
           gcloud beta services identity create --service=pubsub.googleapis.com --project=<プロジェクトID>
           ```
        3. コマンド実行後に再度「すべて付与」を試す
   6. 「次へ」でコード編集画面に進み、ランタイムは「Node.js 22」（LTS版。Node.js 20はサポート終了のため選ばない）、エントリポイントは `stopBillingOnBudgetAlert` を指定する
   7. `index.js` に以下のコードを貼り付ける

      ```js
      const {google} = require('googleapis');

      exports.stopBillingOnBudgetAlert = async (pubSubEvent) => {
        const pubsubData = JSON.parse(
          Buffer.from(pubSubEvent.data, 'base64').toString()
        );

        // costAmount が budgetAmount を超えた場合のみ課金を停止する
        if (pubsubData.costAmount <= pubsubData.budgetAmount) {
          return;
        }

        const auth = new google.auth.GoogleAuth({
          scopes: ['https://www.googleapis.com/auth/cloud-billing'],
        });
        const billing = google.cloudbilling({version: 'v1', auth: await auth.getClient()});
        const projectName = `projects/${pubsubData.projectId}`;

        await billing.projects.updateBillingInfo({
          name: projectName,
          requestBody: {billingAccountName: ''}, // 空にすることで課金アカウントを切り離す
        });
      };
      ```

   8. `package.json` に以下の内容を追加する

      ```json
      {
        "name": "stop-billing-on-budget-alert",
        "main": "index.js",
        "dependencies": {
          "googleapis": "^140.0.0"
        }
      }
      ```

   9. 「デプロイ」をクリックし、完了まで待つ（数分かかる）

5. **動作確認**
   - Cloud Functionsの詳細画面 →「ログ」タブでデプロイ・実行ログを確認できる
   - 実際に予算超過を起こさずテストしたい場合は、Pub/Subトピックに手動でテストメッセージ（`costAmount` が `budgetAmount` を超える形のJSON）を発行して動作確認する方法もある

**リスク・注意点（必ず確認すること）：**

- 発動すると **Storageだけでなく、Firestore・Authenticationを含むプロジェクト全体の有料機能が停止する**（アプリが実質ダウンする）
- 予算データの反映には数時間〜1日程度のタイムラグがあり、閾値ちょうどで止まるとは限らない（多少の超過はあり得る）
- 一度課金アカウントが切り離されると、**再開には手動での再設定が必要**（自動復旧しない）
- 上記を踏まえ、まずは低めの予算額（例: 月額500円程度）で運用し、様子を見ながら調整することを推奨する

- [ ] Blazeプランへのアップグレードが完了した

## 2. Next.jsプロジェクトのscaffolding

**この章はターミナル操作。Claude Codeが代行可能。** ユーザーが章1を完了した後に実施する。

### 2.1 プロジェクト作成コマンド

リポジトリルート（`D:\develop\tayori`）で以下を実行する。

```bash
npx create-next-app@latest . --typescript --tailwind --app --src-dir --import-alias "@/*" --eslint
```

オプションの意図:

| オプション             | 理由                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `--typescript`         | 基本設計書の技術スタックに準拠                                       |
| `--tailwind`           | Tailwind CSS標準採用のため                                           |
| `--app`                | App Router必須（基本設計書4.2節のディレクトリ構造前提）              |
| `--src-dir`            | 基本設計書10.1節が `src/` 配下のディレクトリ構成を前提としているため |
| `--import-alias "@/*"` | 基本設計書内のimportパス表記（`src/lib/...` 等）と揃えるため         |
| `--eslint`             | 最低限のLintを最初から有効化                                         |

既存の `docs/` `layouts/` `.claude/` `.gitignore` `CLAUDE.md` `README.md` と衝突しないか、実行前に確認すること（`create-next-app` は既存ファイルがあると警告を出す場合がある）。

### 2.2 追加パッケージのインストール

```bash
npm install firebase
npm install --save-dev vitest @vitejs/plugin-react @testing-library/react @testing-library/jest-dom jsdom @firebase/rules-unit-testing
```

| パッケージ                                            | 用途                                       |
| ----------------------------------------------------- | ------------------------------------------ |
| `firebase`                                            | Firebase SDK（Auth / Firestore / Storage） |
| `vitest`, `@vitejs/plugin-react`                      | テストランナー（基本設計書9.2節）          |
| `@testing-library/react`, `@testing-library/jest-dom` | コンポーネントテスト                       |
| `jsdom`                                               | Vitestのブラウザ環境シミュレーション       |
| `@firebase/rules-unit-testing`                        | Security Rulesのユニットテスト             |

### 2.3 shadcn/ui の導入

```bash
npx shadcn@latest init
```

対話式プロンプトが表示されたら、既存の `tailwind.config.ts`（基本設計書3.6節のデザイントークンをこの後で反映するため、初期値は既定のままでよい）と `src/app/globals.css` を上書きしてよいか聞かれる場合は許可する。

### 2.4 環境変数ファイルの作成

`.env.local` をプロジェクトルートに新規作成し、章1.2で控えた6つの値を設定する。

```
NEXT_PUBLIC_FIREBASE_API_KEY=（firebaseConfig.apiKey の値）
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=（firebaseConfig.authDomain の値）
NEXT_PUBLIC_FIREBASE_PROJECT_ID=（firebaseConfig.projectId の値）
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=（firebaseConfig.storageBucket の値）
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=（firebaseConfig.messagingSenderId の値）
NEXT_PUBLIC_FIREBASE_APP_ID=（firebaseConfig.appId の値）
```

**このファイルはユーザー自身が値を入力すること。** Claude Codeに実際のAPIキー等の値を口頭・チャットで伝える必要はない（ファイルに直接書き込めばよい）。

### 2.5 `.gitignore` の確認

`create-next-app` が生成する `.gitignore` に `.env*` が含まれていることを確認する（既存の `.gitignore` にも `.env*.local` `.env` の記載あり。二重に記載されても問題はないが、`.env.local` が確実に除外されているか `git status` で最終確認する）。

### 2.6 動作確認

```bash
npm run dev
```

`http://localhost:3000` にアクセスし、Next.jsの初期画面が表示されればscaffolding成功。

### 2.7 このステップの完了条件

- [ ] `npx create-next-app` でプロジェクトが生成された
- [ ] `firebase` および テスト関連パッケージがインストールされた
- [ ] `shadcn/ui` が初期化された
- [ ] `.env.local` に6つの値が設定された
- [ ] `.env.local` が `git status` で追跡対象外（untracked扱いされない = ignore対象）になっていることを確認した
- [ ] `npm run dev` でローカル起動を確認した

## 3. Vercelプロジェクトのセットアップ

**この章はブラウザでの手動操作が必須。Claude Codeは代行できない。** 章2の完了後、最初のGitHub pushの準備ができてから実施する。

### 3.1 前提: GitHubリポジトリの準備

Vercelの自動デプロイはGitHub連携が前提となる。現在このリポジトリはローカルのみのため、以下が必要になる（**pushはユーザーが手動で行う運用**、`.claude/rules/restrictions.md` 参照）。

1. GitHub上に新規リポジトリを作成する（例: `tayori`）
2. ユーザー自身が `git remote add origin <URL>` と `git push -u origin main` を実行する（Claude Codeは実行しない）

### 3.2 Vercelプロジェクトの作成

1. https://vercel.com/ にアクセスし、GitHubアカウントでログインする
2. 「Add New...」→「Project」をクリック
3. 先ほど作成したGitHubリポジトリ（`tayori`）をImportする
4. Framework Presetは自動検出で「Next.js」になっていることを確認する
5. 「Environment Variables」セクションで、`.env.local` に設定した6つの `NEXT_PUBLIC_FIREBASE_*` を1つずつ入力する（コピー&ペースト）
6. 「Deploy」をクリックする

### 3.3 デプロイ後の確認

1. デプロイ完了後、発行されたURL（例: `tayori-xxxx.vercel.app`）にアクセスし、Next.jsの初期画面が表示されることを確認する
2. Firebase Console の Authentication →「Settings」→「承認済みドメイン」に、VercelのURL（`tayori-xxxx.vercel.app`）を追加する（**これを忘れるとVercel上でGoogleログインが失敗する**）

### 3.4 このステップの完了条件

- [ ] GitHubリポジトリを作成し、ユーザーが手動でpushした
- [ ] Vercelプロジェクトを作成し、GitHubリポジトリとImport連携した
- [ ] Vercelの環境変数に6つの `NEXT_PUBLIC_FIREBASE_*` を設定した
- [ ] 初回デプロイが成功し、URLでアクセスできることを確認した
- [ ] Firebase Authentication の承認済みドメインにVercelのURLを追加した
