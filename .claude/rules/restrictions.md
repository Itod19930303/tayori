# 禁止・制約ルール

## 1. Git プッシュ・プル禁止

以下のコマンドは料金が発生するため、ユーザーの明示的な指示なしに実行しない。

禁止コマンド:
- `git push` （オプション問わず）
- `git fetch`
- `gh pr create` / `gh pr merge` / `gh release`

対応: 作業完了後、「プッシュが必要な場合はユーザーが手動で実行してください」と案内する。

## 2. 削除コマンド禁止

以下の操作はユーザーの明示的な確認なしに実行しない。

禁止操作:
- `Remove-Item` / `rm` / `del` によるファイル・ディレクトリ削除
- `git branch -D` / `git branch -d` によるブランチ削除
- `git reset --hard` / `git clean -f` による変更の破棄
- データベースの `DROP` / `DELETE` 文
- Firebase Storage / Firestore ドキュメントの削除API呼び出し

対応: 削除が必要と判断した場合は、対象・理由・影響範囲を提示してユーザーに確認を取る。

## 3. ソースコード修正時の依存関係確認

ソースコードを修正する前に、以下を必ず確認する。

### 確認手順

1. **変更対象の特定** — 変更するファイル・関数・型・定数を明確にする
2. **依存関係の調査** — 変更対象を参照している箇所をプロジェクト全体で検索する
3. **影響範囲の報告** — 影響が出る箇所をユーザーに提示する

### 報告フォーマット

影響がある場合は修正前に以下を提示する。

```
【依存関係レポート】
変更対象: <ファイル:行番号 / 関数名 / 型名>
影響箇所:
  - <ファイルパス:行番号> — <影響の内容>
  - ...
リグレッションテスト対象:
  - <テストファイルまたはテストすべき機能>
  - ...
```

### 影響が広い場合

影響箇所が多い、または既存テストのないコードに変更が及ぶ場合は、  
修正前にリグレッションテスト計画をユーザーと合意してから作業を進める。
